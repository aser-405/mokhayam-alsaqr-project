# باك اند مخيم الصقر — PHP + MySQL

## ⚠️ تنويه أمان - كلمات السر غير مشفرة حاليا 
تم ازالة التشفير في عمود `password_hash()` — هلق الباسورد **محفوظ نص عادي (plain text)** بعمود
`password_plain` بجدول `users`، ومقارنته بشكل مباشر بملف `api/login.php`.

هاد مناسب لمرحلة التطوير/الاختبار المحلي بس. **قبل ما ترفع النظام لاستضافة حقيقية أو
يشتغل عليه ناس فعليًا**، لازم ترجّع التشفير، لأنه أي حدا يوصل لقاعدة البيانات (نسخة
احتياطية، اختراق، أو حتى استعلام SQL بالغلط) بيشوف كل الباسوردات مباشرة بدون أي عائق.

**لما تصير جاهز ترجع التشفير:**
1. بملف `api/login.php`: رجّع `password_verify($password, $user['password_plain'])`
   واستبدل عمود `password_plain` بـ `password_hash` بالاستعلام.
2. بملف `seed_admin.php`: رجّع سطر `$hash = password_hash($password, PASSWORD_DEFAULT);`
   واحفظ `$hash` بدل `$password`.
3. بقاعدة البيانات: `ALTER TABLE users CHANGE password_plain password_hash VARCHAR(255) NOT NULL;`
   وأعد إنشاء المستخدمين (لأنه القيم القديمة نص عادي مش hash).

---

## عن التشفير (تفصيل إضافي لو حبيت ترجعه لاحقًا)
`password_hash()` هي دالة PHP القياسية اللي بتحوّل كلمة المرور إلى **hash أحادي الاتجاه**
(بخوارزمية bcrypt افتراضيًا) — ما حدا يقدر "يفك" الـ hash ويشوف كلمة المرور الأصلية، حتى
صاحب السيرفر نفسه. هاي الطريقة المعتمدة عالميًا (نفسها يلي بتستخدمها بنوك ومواقع كبيرة).

## هيكلية المشروع
```
backend/
  api/                    ← كل نقاط النهاية (Endpoints)
    login.php             POST  تسجيل دخول
    logout.php            POST  تسجيل خروج
    dashboard_stats.php   GET   إحصائيات لوحة التحكم        (يتطلب تسجيل دخول)
    families.php          GET/POST  قائمة العائلات + إضافة   (يتطلب تسجيل دخول)
    family_lookup.php      GET   بحث عن عائلة برقم البطاقة    (يتطلب تسجيل دخول)
    individuals.php        GET/POST  قائمة الأفراد + إضافة    (يتطلب تسجيل دخول)
    aid_types.php           GET/POST  أنواع المساعدات + إضافة  (يتطلب تسجيل دخول)
    distributions.php       GET/POST  سجل التوزيع + إضافة      (يتطلب تسجيل دخول)
    join_requests.php       GET/POST  مراجعة طلبات الانضمام    (يتطلب تسجيل دخول)
    submit_join_request.php POST  تقديم طلب انضمام            (عام — بدون تسجيل دخول)
    categories_stats.php    GET   إحصائيات الفئات الخاصة       (يتطلب تسجيل دخول)
  config/
    db.php                إعدادات الاتصال بقاعدة البيانات
  includes/
    auth.php               دالة التحقق من تسجيل الدخول (الجلسة)
    response.php            دوال مساعدة للردود بصيغة JSON
  schema.sql                بنية قاعدة البيانات كاملة
  seed_admin.php             سكربت إنشاء أول مستخدم مدير (شغّله مرة وحدة ثم احذفه)
```

الواجهة الأمامية (مجلد `dashboard/` من التسليم السابق) لازم تنحط **جنب** مجلد `backend/`
مباشرة، متل هيك:
```
mokhayam-alsaqr/
  backend/     ← هذا المجلد
  dashboard/   ← ملفات الواجهة (index.html, dashboard.html, families.html...)
```
لأنه ملفات الواجهة بتنادي API بمسار نسبي `../api/...` (شوف `API_BASE` بأول ملف `dashboard/js/app.js`).

## خطوات التشغيل (على جهازك أو استضافة تدعم PHP + MySQL)

1. **أنشئ قاعدة البيانات**: استورد ملف `schema.sql` كامل (phpMyAdmin أو أمر `mysql`):
   ```
   mysql -u root -p < schema.sql
   ```
2. **عدّل بيانات الاتصال** بملف `config/db.php` (اسم المستخدم، الباسورد، اسم قاعدة البيانات).
3. **شغّل السيرفر** — إذا عندك PHP محلي:
   ```
   php -S localhost:8000
   ```
   وافتح `http://localhost:8000/../dashboard/index.html` (أو اربط دومين/استضافة حقيقية
   وحط المجلدين `backend` و`dashboard` بجذر الموقع).
4. **أنشئ أول مستخدم مدير**: افتح بالمتصفح `seed_admin.php` مرة وحدة (عدّل الإيميل
   والباسورد جوا الملف قبل ما تشغّله)، ثم **احذف الملف فورًا** من السيرفر.
5. **سجّل دخول** من `dashboard/index.html` بالإيميل والباسورد يلي أنشأتهم.

## شو شغّال فعليًا على قاعدة البيانات الآن (مش تجريبي)
- **تسجيل الدخول / الخروج** — جلسة حقيقية بالسيرفر.
- **لوحة التحكم** — كل الأرقام محسوبة مباشرة من قاعدة البيانات.
- **العائلات** — القائمة، والإضافة (مع توليد رقم بطاقة تلقائي حقيقي `FAM-00001‎` مبني على
  الـ id، ما بيتكرر حتى لو أكتر من موظف بيضيف بنفس اللحظة).
- **طلبات الانضمام** — القائمة الحقيقية، والقبول (بينشئ عائلة + أفراد تلقائيًا)، والرفض.
- **نموذج تسجيل العائلات العام** (`register.html`) — أي شخص بالمخيم يقدر يعبّيه بدون
  تسجيل دخول، والطلب بيوصل مباشرة لصفحة "طلبات الانضمام" لمراجعة الإدارة.

## شو لسا واجهته تجريبية (بس الـ API جاهز ومطابق لنفس الأسلوب)
- **الأفراد، أنواع المساعدات، سجل المساعدات، الفئات الخاصة، توزيع بالمسح** — الجداول
  والفورمات موجودة بالواجهة، والـ endpoints (`individuals.php`, `aid_types.php`,
  `distributions.php`, `categories_stats.php`, `family_lookup.php`) جاهزة وشغالة، بس
  الواجهة لسا ما اتربطت فيهم (زي `families.html` بالضبط). لو حابب أكملها بنفس
  النمط قلي وبربطها.

## ملاحظة مهمة عن قبول طلبات الانضمام
لما تقبل طلب انضمام، النظام بينشئ سجلات "أفراد" تلقائيًا من قائمة الأسماء والأعمار
المُدخلة بالفورم العام. بما إنه الفورم ما بياخد جنس كل فرد بالاسم (بس عدد الذكور
والإناث الإجمالي)، النظام بيوزّع الجنس تلقائيًا بالتسلسل حسب هالعدد — يعني ممكن
يحتاج تصحيح يدوي بسيط من صفحة "الأفراد" لو الترتيب مو مطابق تمامًا. رقم الهوية لكل
فرد (غير رب الأسرة والزوجة) بينحط مؤقتًا (`TMP-...`) للازم تستبدله برقم الهوية
الحقيقي لما يوصلك.

## ملاحظة تشخيصية (لو رجعت رسالة "تعذّر الاتصال بالسيرفر" رغم إنه الطلب رجع 200)
لو شفت بتبويب Network إنه `login.php` (أو أي endpoint) رجع **200** بس الواجهة لسا عم
تطلع رسالة خطأ، السبب المرجّح إنه في تحذير/ملاحظة PHP بسيطة (Warning/Notice) انطبعت
قبل الـ JSON وخربطته، فالمتصفح ما قدر يفهم الرد كـ JSON صحيح.

هالنسخة صار فيها حل جذري للموضوع: `includes/response.php` صار يجمع أي خرج (output
buffering) ويمسح أي تحذير غريب قبل ما يرسل الـ JSON، وبالإضافة عطّلت طباعة الأخطاء
بالرد نفسه (`display_errors = 0`) لتبقى الأخطاء تنكتب بملف اللوج بس، مش بجسم الرد.
لو استمرت المشكلة، افتح تبويب **Response** (مو Preview) بأدوات المطوّر وشوف هل في
نص قبل أول `{` — هيك بنعرف مصدر التحذير بالضبط.

## تحديث: شيل كل البيانات التجريبية + تفعيل الحذف والتصدير والبحث
- **ما في ولا صف/بطاقة وهمية بأي صفحة** — كل الجداول (العائلات، الأفراد، أنواع
  المساعدات، الفئات الخاصة، سجل التوزيع) بتبلش فاضية تمامًا وتتعبى فقط من الفورمات
  الحقيقية.
- **الفئات الخاصة صارت جدول حقيقي قابل للتعديل** (`special_categories`) بدل قيم
  ثابتة — من صفحة "الفئات الخاصة" فيك تضيف أي فئة جديدة بلونها الخاص، وتحذفها،
  وبيتحدّث عدد الأفراد المرتبطين فيها تلقائيًا.
- **حذف حقيقي مفعّل بكل مكان**: حذف عائلة/فرد/نوع مساعدة/عملية توزيع/فئة خاصة
  فردي، بالإضافة لأزرار "حذف الكل" (العائلات، الأفراد، سجل التوزيع) — كلها بتطلب
  تأكيد قبل التنفيذ لأنها نهائية.
- **بحث حي مفعّل**: بصفحات العائلات، الأفراد، وسجل المساعدات — بيبحث بالسيرفر
  مباشرة (مو مجرد فلترة بالمتصفح) فيشتغل صح حتى مع آلاف السجلات لاحقًا.
- **تصدير Excel حقيقي**: بصفحات العائلات، الأفراد، وسجل المساعدات — زر "تصدير
  Excel" بيحوّل الجدول المعروض حاليًا (بعد أي بحث/فلترة) لملف `.xlsx` قابل
  للتنزيل مباشرة، باستخدام مكتبة SheetJS (تحميلها من CDN، فلازم اتصال إنترنت
  عند الاستخدام، ولو انقطع الاتصال بيطلع تنبيه واضح).
- **توزيع بالمسح صار حقيقي بالكامل**: البحث برقم البطاقة بيتحقق فعليًا من قاعدة
  البيانات (مش بيانات وهمية ثابتة)، وقائمة أنواع المساعدات وقائمة "آخر عمليات
  التوزيع اليوم" كلها حقيقية.

### ملاحظة عن "حذف الكل"
أزرار "حذف الكل" بتحذف الصفوف **نهائيًا بدون نسخة احتياطية**. لو بدك حماية إضافية
لاحقًا (تأكيد مزدوج، أو أرشفة بدل حذف فعلي)، قلي وبضيفها.

## صفحة جديدة: تحقق من حالة التسجيل (`dashboard/check-status.html`)
صفحة عامة (بدون تسجيل دخول) — أي شخص يدخل رقم هويته ويعرف فورًا:
- **مسجّل** — مع رقم البطاقة وصفته (رب أسرة / فرد بالعائلة)
- **قيد المراجعة** — لسا طلبه ما انبت فيه
- **مرفوض** — طلب سابق انرفض
- **غير مسجّل** — مع رابط مباشر لصفحة التسجيل

مربوطة بملف `api/check_family_status.php` (endpoint عام برضو، بدون تسجيل دخول).

⚠️ **ملاحظة خصوصية مهمة**: هاد الـ endpoint مقصود يرجع أقل معلومات ممكنة (بس حالة
التسجيل ورقم البطاقة)، بس بما إنه عام وبدون تسجيل دخول، أي حدا يعرف رقم هوية شخص
تاني (أو يجرب أرقام عشوائية) بيقدر يتحقق من حالته. إذا حابب حماية أقوى لاحقًا (متل
طلب رمز تحقق SMS قبل ما يطلع النتيجة)، قلي وبضيفها.

## تنظيف عام على المشروع
- شلت مربع "بحث سريع Ctrl+K" من القائمة الجانبية بكل الصفحات (كان شكلي بس، غير شغّال).
- شلت أزرار "استيراد"، "بطاقات QR"، "تصنيف المربعات"، "نموذج" من صفحة العائلات (كانت
  غير مفعّلة وبتوهم المستخدم إنها شغالة).

## توزيع مساعدة على كل العائلات دفعة وحدة
بفورم "إضافة يدوي" بصفحة سجل المساعدات، صار في خيار (checkbox) بالأعلى:
**"توزيع على كل العائلات المسجّلة دفعة وحدة"**. لما تفعّله، حقل اختيار العائلة
بيختفي، وعند الحفظ بينسجّل استلام هالمساعدة (نفس النوع والعدد والتاريخ) لكل
عائلة مسجّلة بالنظام بعملية وحدة (مع تأكيد قبل التنفيذ لأنها بتأثر على كل
العائلات).

⚠️ ملاحظة: كل ضغطة على هالخيار بتنشئ سجل توزيع جديد لكل عائلة، فإذا ضغطت
عليه مرتين بالغلط رح ينسجل التوزيع مرتين لكل عائلة. النظام حاليًا ما بيمنع
هيك تكرار تلقائيًا (ولا الإدخال اليدوي لعائلة وحدة بيمنعه أصلًا) — إذا حابب
حماية من التكرار لاحقًا (متل: يوم واحد بس لكل نوع مساعدة لكل عائلة)، قلي
وبضيفها.

## ميزات جديدة: الأدوار والصلاحيات + منع التكرار + استيراد Excel

### 1) منع تكرار التوزيع
صار في قيد بقاعدة البيانات (`UNIQUE KEY`) يمنع تسجيل نفس نوع المساعدة لنفس العائلة
بنفس التاريخ مرتين. عمليًا:
- **إضافة يدوية لعائلة وحدة**: لو حاولت تسجّل تكرار، بيطلعلك خطأ واضح "هذه العائلة
  استلمت هذا النوع من المساعدة بنفس التاريخ مسبقًا" وما بيتسجل.
- **توزيع دفعة على كل العائلات**: بيتخطى بصمت أي عائلة استلمت هذا النوع بنفس
  التاريخ من قبل، وبيرجعلك بالنتيجة عدد العائلات يلي انسجلت فعليًا وعدد يلي
  انتخطّت.

### 2) الأدوار والصلاحيات
- **مدير النظام**: صلاحية كاملة — كل الصفحات، كل عمليات الحذف، إدارة المستخدمين
  والإعدادات.
- **مدخل بيانات**: صلاحيات محدودة وقابلة للتخصيص — افتراضيًا (لوحة التحكم،
  العائلات، طلبات الانضمام) بس، وما بيقدر يعمل أي عملية حذف إطلاقًا (حتى لو
  الصفحة نفسها مسموحة إله) — الحذف محجوز للمدير دايمًا.

### 3) صفحة "المستخدمون" (`users.html`، مدير فقط)
إضافة مستخدمين جدد (اسم، إيميل، باسورد، صلاحية)، وحذفهم. ما بتقدر تحذف حسابك
الخاص وأنت مسجّل دخول فيه (حماية من قفل نفسك بره النظام بالغلط).

### 4) صفحة "الإعدادات" (`settings.html`، مدير فقط)
تحديد بالضبط أي صفحات تظهر لمستخدمي "مدخل بيانات" بالقائمة الجانبية، عن طريق
تحديد/إلغاء تحديد من قائمة checkboxes وحفظ. التغيير بينطبق فورًا (بمرة الدخول
الجاية لمستخدم مدخل البيانات، أو بريفريش الصفحة).

⚠️ **مهم**: أول ما تشغّل النظام على قاعدة بيانات جديدة، أول مستخدم (يلي بتعمله
عبر `seed_admin.php`) لازم يكون دوره "مدير" (هيك هو مضبوط بالسكربت افتراضيًا)
عشان تقدر تدخل على صفحة الإعدادات والمستخدمين وتضيف بقية الحسابات.

### 5) استيراد عائلات من Excel (`families.html`، مدير فقط)
زر "استيراد من Excel" بصفحة العائلات — بيفتح نافذة اختيار ملف، وبيقرأ الملف
بالمتصفح مباشرة (بدون رفعه كملف خام للسيرفر)، ويرسل البيانات كصفوف جاهزة.

**الأعمدة المتوقعة بالصف الأول من ملف الإكسل (نفس الأسماء بالضبط):**
```
اسم رب الأسرة | رقم هوية رب الأسرة | تاريخ ميلاد رب الأسرة | الحالة الاجتماعية
اسم الزوجة | رقم هوية الزوجة | تاريخ ميلاد الزوجة | عدد أفراد الأسرة
```
- الحقول المطلوبة: الاسم، رقم الهوية، وتاريخ الميلاد (لرب الأسرة). الباقي اختياري.
- تواريخ الميلاد: فيك تكتبها كتاريخ فعلي بخانة الإكسل (بيتعرف عليها تلقائيًا)
  أو كنص بصيغة `YYYY-MM-DD`.
- أي صف رقم هويته مسجّل مسبقًا، أو ناقصه بيانات أساسية، بيتخطّى وبيوصلك تقرير
  بالضبط شو انتخطّى وليش.

## إصلاح: وين شكاوى صفحة الهبوط بتوصل؟
كانت شكاوى صفحة الهبوط العامة (`landing-page.html`) بس بتعرض رسالة شكر بالواجهة
بدون ما تتخزن أي مكان — هلق صلحتها:
- شكوى جديدة بتتخزن بجدول `complaints` عبر endpoint عام جديد
  (`api/submit_complaint.php`، بدون تسجيل دخول).
- صفحة إدارية جديدة **`dashboard/complaints.html`** لعرض ومراجعة الشكاوى (فيها
  حالة "جديدة" / "تمت المراجعة"، وحذف — الحذف للمدير فقط).
- هاي الصفحة صارت جزء من نظام الصلاحيات (تقدر تحددها بصفحة الإعدادات لدور
  "مدخل بيانات" متل باقي الصفحات).

⚠️ **مهم جدًا عن مكان النشر**: صفحة الهبوط (`landing-page.html`) لازم تكون
بنفس مستوى مجلد `backend/` على السيرفر (يعني `backend/` جنبها مباشرة، مش
جواها ولا بعيد عنها) عشان يشتغل المسار `backend/api/submit_complaint.php`
يلي حطيته بالكود. إذا نشرتها بمكان تاني، لازم تعدّل هالمسار بالسكربت بآخر
الصفحة.

   أعمدة محددة بس. هلق بيقبل أسماء بديلة شائعة (مثل "الاسم رباعي" بدل "اسم
   رب الأسرة")، وتاريخ الميلاد صار اختياري بالكامل (كثير كشوفات إسكان ما فيها
   تواريخ ميلاد)، وبيطبّع الحالة الاجتماعية من صيغ مثل "متزوج / متزوجة"،
   وبيتعامل صح مع أرقام الهوية/الجوال يلي بتوصل كأرقام عشرية من الإكسل.

2. **عدد العائلات (كان ثابت "171")**: صار ديناميكي بالكامل، بيتحدث من قاعدة
   البيانات الفعلية بكل مرة.

3. **الجنس بفورم العائلة**: ضفت حقل "الجنس" لرب الأسرة (اختياري).

4. **البحث بتوزيع بالمسح**: صرت تقدر تكتب رقم بس (متل `1` أو `14`) بدل
   `FAM-00001` كامل، وبيتحول تلقائيًا.

5. **رقم البطاقة ورقم الجوال بجدول العائلات**: صاروا أعمدة ظاهرة بالجدول
   مباشرة.

6. **زر التعديل (Edit) فعّال الآن بصفحتي العائلات والأفراد**: بيفتح نفس فورم
   الإضافة معبّى ببيانات السجل، وبيحفظ التعديلات بدل إنشاء سجل جديد. تاريخ آخر
   تعديل بيتسجل تلقائيًا بعمود `updated_at` (يتحدث لحاله بكل UPDATE، من MySQL
   نفسه، بدون أي كود إضافي).

7. **صلة القرابة عند قبول طلبات الانضمام**: بدل ما كل أفراد العائلة ينحطوا
   "أخرى"، هلق بينحددوا "ابن" أو "ابنة" تلقائيًا حسب الجنس المحسوب.

⚠️ **لازم تعيد استيراد `schema.sql`** (تغييرات كتير على الجداول: تاريخ الميلاد
صار اختياري، عمود الجنس، عمود الجوال، عمود آخر تحديث). لو عندك بيانات موجودة
ما بدك تخسرها، استخدم أوامر الـ `ALTER` المكتوبة تعليق بأول كل جدول بدل إعادة
الإنشاء الكامل.

## ميزة جديدة: الموقع الجغرافي (مربعات المخيم)
قسم جديد كامل لتصنيف العائلات جغرافيًا:

- **صفحة "الموقع الجغرافي"** (`zones.html`) — عرّف مربعات/مناطق المخيم (مثال:
  "مربع أ"، "الحي الشرقي") بالاسم واللون، وشوف عدد العائلات بكل مربع تلقائيًا.
  الحذف للمدير فقط؛ الإضافة والعرض حسب صلاحيات "مدخل بيانات" العادية (قابلة
  للتحديد من صفحة الإعدادات).
- **فورم "إضافة عائلة"** — صار فيه حقل "المربع/المنطقة" (اختياري)، وجدول
  العائلات بيوري عمود المربع لكل عائلة.
- **صفحة التسجيل العامة** (`register.html`) — صار فيها حقل اختيار المربع
  (اختياري)، مربوط بـ endpoint عام جديد (`api/public_zones.php`) بيرجع بس
  أسماء المربعات (بدون أي بيانات حساسة).
- **قبول طلبات الانضمام** — المربع يلي اختاره مقدّم الطلب بينتقل تلقائيًا
  للعائلة الجديدة لما يتقبل الطلب، وبيظهر بكرت المراجعة قبل القبول.

⚠️ **تعديلات كبيرة على الجداول هالمرة كمان** (جدول `zones` جديد، وعمود
`zone_id` بجدولي `families` و`join_requests`) — لازم تعيد استيراد
`schema.sql` من جديد، أو تستخدم أوامر الـ `ALTER` المعلّقة بأول كل قسم.

## دفعة تحسينات: فورمات + ترقيم صفحات + فلاتر + إصلاح الاستيراد

1. **التنسيق**: صلحت مشكلة الفراغات الكبيرة بين الأعمدة بجدول العائلات (كان
   الجدول يتمدد بالكامل ويوزّع الفراغ بشكل غير متساوي بين الأعمدة القصيرة).

2. **ترقيم الصفحات**: جدول العائلات صار فيه ترقيم صفحات حقيقي تحت الجدول
   (1، 2، 3...) مع اختيار عدد الصفوف بالصفحة (20/50/100، افتراضي 20).

3. **فلاتر**: صف فلاتر جديد فوق الجدول — فلترة حسب الحالة الاجتماعية، المربع/
   المنطقة، والجنس. بتشتغل مع بعضها ومع البحث بنفس الوقت، وبترجّع للصفحة
   الأولى تلقائيًا كل ما غيّرت فلتر. زر "تصدير Excel" بيصدّر البيانات المفلترة
   كاملة (مش بس الصفحة الظاهرة حاليًا).

4. **إصلاح الاستيراد (تاريخ الميلاد + الحالة الاجتماعية)**: السبب الأرجح كان
   صيغة التاريخ — لو تاريخ الميلاد بملفك مكتوب كنص (يوم/شهر/سنة، الشائع
   بمنطقتنا)، الكود القديم كان أحيانًا يفهمه بالغلط كـ (شهر/يوم/سنة على
   الطريقة الأمريكية). هلق بيتعرف صراحة على صيغة يوم/شهر/سنة، وبيتعامل صح مع
   أرقام تواريخ إكسل الخام (لو الخلية مش منسّقة كتاريخ أصلاً)، وبيوسّع أسماء
   الأعمدة المقبولة لتاريخ الميلاد. الحالة الاجتماعية صارت تتعرف على صيغ أكتر
   ("عزباء"، "مطلقة"، "أرملة"...) مش بس "متزوج/متزوجة".

جرب الاستيراد من جديد وقولّي إذا التاريخ والحالة الاجتماعية صاروا يدخلوا صح.
